# 英伦慢游 · 产品需求说明

版本：当前成果整理版｜日期：2026-10-09｜负责人：王誉翔  
定位：AI 旅行规划方向的可交互原型。当前暂停功能扩展，整理已有成果；不以文档中的后续计划表示已实现。

## 1. 产品目标与问题

面向希望用中文规划英国旅行的人，把“我想怎么旅行”衔接到“想去哪里、每天怎么看、哪些信息要确认”。

当前要解决的三个问题：

1. 还没有明确目的地时，需要能激发兴趣的地点与故事。
2. 有了想法后，需要把城市、天数与个人偏好整理成看得懂的结构。
3. 浏览安排时，需要区分有来源的信息、项目估算与尚待确认的内容。

当前交付目标是完成发现、需求收集、示例浏览与资料核对的完整体验，不宣称已自动产出可直接执行的个人行程。

## 2. 目标使用场景

以下为产品设计场景，尚未通过正式用户研究验证。

| 场景 | 需求 | 当前承接方式 |
| --- | --- | --- |
| 尚未决定具体去处 | 先找到喜欢的氛围和地点 | 旅行心情、六篇故事、按城市浏览 |
| 已决定英国多城旅行 | 整理城市、日期、节奏与固定安排 | 需求表单、条件确认、逐日示例 |
| 已有一天的大致安排 | 检查时间冲突，追溯参观信息 | 地点资料、交通参考、手填单日检查 |

## 3. 产品范围

| 类别 | 当前状态 |
| --- | --- |
| 目的地与天数 | 伦敦、牛津、巴斯；需求表单支持 3–7 天 |
| 发现内容 | 已实现：六篇原创地点故事、城市筛选、故事与地图选择联动 |
| 需求收集 | 已实现：想法、城市、日期／日期未定、天数、首尾城市、兴趣、节奏、必去地点与固定安排 |
| 逐日规划 | 示例：根据城市顺序、首尾与天数组合固定样例；不是模型生成，个人偏好不驱动真实安排 |
| 资料查询与检查 | 已实现：30 个地点、3 对交通参考、地点搜索／详情／交通／单日检查四项功能 |
| 调整入口 | 只记录当前会话中的调整意图，不修改行程 |
| 未接入 | 模型自动规划、自然语言解析、实际替换／锁定／撤销、本地保存恢复 |
| 不在当前产品范围 | 机酒推荐、预订支付、账号、多人协作、实时票额与导航 |

## 4. 核心路径与页面

**从灵感开始：**首页 → 发现故事 → 选中地点 → 带入规划需求 → 填写与确认 → 逐日示例。

**直接计划：**首页输入想法／选择旅行心情 → 填写需求 → 确认条件 → 逐日示例 → 地点详情。

**核对安排：**资料与检查 → 搜索地点或查询交通 → 手填日期、时段、地点与固定活动 → 查看冲突与待确认项。

| 页面 | 要回答的问题 | 主要内容 |
| --- | --- | --- |
| 首页 `/` | 我想以什么方式旅行？ | 摄影、旅行主张、计划／发现双入口、三种心情、故事预览 |
| 发现 `/discover` | 这里为什么值得去？ | 三城故事、重点标记、参观资料、以此开始计划 |
| 规划 `/plan` | 我的需求是什么？安排如何呈现？ | 需求、确认、示例工作区、详情、调整便笺 |
| 直接示例 `/plan/example` | 产品成果是什么样？ | 七天固定示例的直接入口 |
| 资料与检查 `/explore` | 信息依据是什么？时间是否有明显冲突？ | 地点、交通与单日检查三个面板 |

## 5. 功能与验收要求

“已实现”指代码中有对应能力；不等于最新版每项界面操作都已通过人工验收。

| 功能 | 主要规则 | 验收要求 | 状态 |
| --- | --- | --- | --- |
| 首页计划入口 | 想法必填，最多 500 字；旅行心情带入对应城市、天数与偏好 | 空输入有提示，带入内容可在需求页修改 | 已实现 |
| 故事发现 | 默认显示伦敦两点；可切城市或全部；有效故事链接打开对应内容 | 故事与地图选择一致，地点可带入需求且保留已有个人输入 | 已实现 |
| 需求与确认 | 仅支持三城、3–7 天；首尾属于所选城市；日期须有效 | 缺项定位清楚，确认页保留填写条件；说明未参与示例编排的字段 | 已实现 |
| 示例工作区 | 按天切换、选择地点、打开详情；样例可能重复 | 持续显示示例边界，不使用虚构执行记录暗示 AI 已规划 | 已实现，内容为示例 |
| 地图 | 只突出重点编号标记；坐标近似，底图保留署名 | 无导航承诺；加载失败有提示与重试，文本内容仍可阅读 | 已实现，最新版故障／视觉复验待补 |
| 地点查询 | 三城各 10 个；支持城市、文本与类型条件 | 可追溯来源和核对日；未知事实显式标注，空结果不伪造内容 | 已实现 |
| 交通参考 | 三对城际路线；官方参考与项目车程、缓冲分开 | 反向查询说明限制；不显示实时班次、价格或余票保证 | 已实现 |
| 单日检查 | 手动填写当地日期、可用时段、地点时段和固定活动 | 识别重叠、超出日范围、跨城时间不足、明确闭馆；其他缺口保留待确认 | 已实现 |
| 调整便笺 | 最多 1,000 字，空白不可提交；只记意图 | 不提示行程修改成功，不出现虚构锁定、撤销或保存成功 | 已实现，非实际修改 |

三城同城往返至少四天等提示来自固定示例的展示结构，不是交通可行性结论。需求表单中的固定安排自由文本不会自动进入单日检查，需另行填写结构化时间与城市。

## 6. 信息与数据规则

- 地点资料保留中英文名称、地址、近似坐标、参观／入场／预约／开放信息、来源及核对日。当前 30 个地点对应 41 个独立地点来源网址，核对日为 2026-10-09。
- 来源内容以本地整理快照提供，不在查询时重新抓取网站。120 个事实字段中有 24 个未知项；不知道的信息不补写为确定事实。
- 当前 7 个地点有常规周时窗，3 个地点有共 17 条明确闭馆日期。它们不覆盖全部节假日、临时关闭或最后入场时间。
- 伦敦—牛津、伦敦—巴斯、牛津—巴斯的项目交通预算为 150／160／170 分钟，各包含 60 分钟缓冲；与官方车程参考分开展示，不能视为实际出行保证。
- 地点停留时长、交通缓冲为项目估算；同城移动、实时班次、延误、余票与全部日期例外尚未核验。
- 故事为原创编辑内容，与地点和来源关联；事实和旅行建议区分。复用城市照片须标明城市印象，保留图片许可与地图署名。

## 7. 失败、未知与状态边界

| 情况 | 当前应有表现 |
| --- | --- |
| 不支持的城市、无效日期／时间、未知地点、缺少输入 | 明确错误并阻止本次操作，不返回假的成功结果 |
| 地点或交通搜索无结果 | 展示空结果或未找到，允许更换条件 |
| 开放时间资料不足 | 显示需确认；常规时间匹配也不能保证当天开放 |
| 固定活动重叠、跨城预留不足 | 指明有关安排与冲突原因；不自动改写行程 |
| 未发现基础时间冲突 | 显示“仍需确认”，不输出整体行程可行保证 |
| 请求失败或地图瓦片失败 | 提示失败与重试；不伪造资料或执行进度 |
| 刷新或离开会话 | 未实现本地保存恢复；不承诺需求与便笺永久保留 |
| 模型缺失 | 只提供示例，不能显示 AI 生成成功 |

接口已设置输入格式、错误状态与 32 KiB 请求上限。内部故障处理已实现，尚未做服务器内部故障注入验证。单日检查暂不支持跨午夜，不把钟面时间差当作夏令时切换时的实际耗时保证。

## 8. 体验取舍与反馈依据

当前设计保持摄影和少量文字主导，统一标题／正文字体角色；偏好、特别安排、故事全文与来源按需展开。工作区采用行程／地图两列，删除地图连线、图例及多余覆盖操作，减少同时呈现的信息。

依据为本人转述的同学与朋友非正式意见：页面打不开或闪动、首页繁琐与缺少特色、字体杂乱、地图内容过多，以及对旅行叙事、地点故事和地图联动的偏好。未开展正式访谈统计，不附虚构人数、逐字引言、满意度或效果提升数字。
