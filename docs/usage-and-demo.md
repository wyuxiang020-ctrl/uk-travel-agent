## 启动

Node.js 24.16 已验证。首次 `npm ci`，配置 `.env.local`（参考 `.env.example`），随后 `npm run build`。不需要网络代理的电脑运行 `npm run start`。

当前电脑的系统代理为 127.0.0.1:7897。PowerShell 中进入工程后，可使用：

```powershell
.\scripts\start-preview.ps1 -ProxyUrl http://127.0.0.1:7897 -NodePath D:\NodeJS\node.exe
```

脚本检查 3005 占用，不擅自关闭其他进程；仅启动本机服务。日志与进程编号在 `work/`。重启前核对已有进程确实属于本项目，停止后再启动。需要代理时须保持代理运行。开发使用 `npm run dev`，同样要在启动 Node 前设置代理变量并启用 `--use-env-proxy`；开发与生产一次只运行一种。

密钥仅在服务端读取，不要放到 `NEXT_PUBLIC_` 变量、备份或 Git 中。本轮 GPT-4.1 最多 1 美元，费用账本沿用 `20261011-gpt41-first`；不要删除记录或换编号重置限额。配置和模型列表可见性不代表账户余额充足。

## 一条完整流程

1. `/plan/details` 填写想法、城市、日期、3–7 天、节奏、必去与固定安排。也可以先在自然语言中说明日期，助手会要求确认。
2. 进入真实规划，先理解需求。有缺失或矛盾会补问，确认结构化条件后才生成。例：11 月 10 日伦敦出发，3 天，博物馆与历史建筑，必须去大英博物馆，第二天 14:00–15:00 与朋友见面。
3. 查看每日安排、少量地图标记、资料来源和待确认事项。执行记录区别模型请求与系统检查，未知开放信息不会变成“已保证开放”。
4. 在“调整具体安排”锁定重要景点。替换、移除或移动参观时，不调用模型；系统检查后先给出差异。应用后形成新版本，失败时原计划保留。
5. 在“让助手重新安排”选择天数与节奏，描述整体修改，例如增加牛津停留一天。此操作会调用模型；固定活动和锁定参观必须保留，不能满足时拒绝候选。修改必去或固定条件需开始新的需求流程。
6. 使用撤销/重做恢复版本，点击“保存到本机”。刷新后从 `/plan/saved` 打开，恢复历史与锁定并重新检查。最多保留最近 20 个版本；撤销后另作修改会替换旧分支。
7. 下载 JSON 备份。可在未打开行程的保存页导入备份，检查通过后再保存。恢复和导入不调用模型，坏记录不覆盖原保存内容。

## 边界与后续人工验收

- 当前只保存一份旅行文档（含版本历史），再次保存另一份会替换该浏览器中的这一份；可先下载旧备份。没有账号、云同步、多设备或多旅行列表。
- 需求表和执行记录未持久化。行程与版本需明确点击保存；未保存的修改刷新后会丢失。
- 固定活动始终保护，景点手动锁定。撤销若会改变当前锁定项，会要求先解锁。
- 缩短天数若会删去固定活动所在日，在模型调用前直接拒绝；若会删去锁定景点所在日，先解锁或保留天数。每个旅行日至少包含一项参观或固定活动，休息通过活动间留白表达，暂不支持完全空白的自由日。
- 城际时长是资料参考加项目估算，不是实时班次；同城导航、余票、预约和具体日期开放仍需人工核对。未新增其他欧洲国家的规划资料。
- 本机单进程使用，无公开服务鉴权/多用户限流，未公开部署。备份只代表本地数据，不是云端签名或真实性证明。
- 真实付费验收覆盖伦敦三日生成与一次局部修改。多城市/天数扩展、错误和预算保护等主要由离线或接口自动化覆盖；未做广泛模型效果评测、真人体验、真机兼容与负载测试。
- 后续人工验收关注：路线是否符合个人偏好、留白是否舒服、说明是否易懂、来源是否足够、修改是否符合预期，以及手机实际操作感受。工程通过不等于这些体验已通过。
